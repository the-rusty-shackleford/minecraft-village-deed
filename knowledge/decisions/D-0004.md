# D-0004 — One trusted list per owner, on a screen

Accepted 2026-09-27. Rusty, told that trust was `/deed trust <player>` run standing in each
village: "I'd much rather there be a unified UI where I can trust people (like the warehouse
manager has) and I want it to apply to all of my villages." Then, offered the ways in: "Both
right click a deed and type /deed with nothing after it (since my friends need to manage trust
for their villages too, but they're not operators)."

D-0001's rule stands (the owner and the players they name are exempt, nobody else); what changes
is where the naming lives: once per owner, not once per village.

## The rule

- **Trust belongs to the owner.** `domain.Roster` (owner, trusted; immutable; never holds the
  owner) is one list per player covering every village they hold, now and later. A deed exempts
  its owner and the players on its owner's roster. `domain.Deed` keeps only the owner; a transfer
  puts the village under the new owner's roster and the old owner is a stranger to it.
- **The screen** (`client.TrustScreen`), drawn like Warehouse Manager's trust panel: every player
  this world has seen (a player-data file, online, or on the roster), online first then by name
  ignoring case (`Roster.rows`), online in green, trusted ticked, the count of ticked in the title
  (a ticked name can sit below the fold of a long list); a click toggles one player. The title's
  hint says how many villages the list covers, or that it will cover any bought later.
- **Two ways in, both every player's:** using (right-clicking) any village deed, whichever village
  it names, opens the user's own list; so does `/deed` with nothing after it. Only `/deed revoke`
  needs an operator. `/deed trust|distrust <player>` stay and edit the same list, from anywhere.
- **The server decides.** A toggle changes only the sender's own roster; naming the sender, or
  trusting a player this world has never seen, changes nothing; every toggle is answered with a
  fresh listing. A listing goes only to a connection that took the channel at login: NeoForge
  refuses a payload to one that did not (a machine's fake player using a deed has none).

## Where it lives

- `Rosters`, saved data `villagedeed_rosters` on the **overworld**, so one list covers villages in
  every dimension (claims stay per dimension in `villagedeed_claims`). Names of the trusted are
  kept beside the ids, since names change and an offline player may be missing from the cache.
- `Exemptions`: the claim's owner, then `Rosters.permits(owner, criminal)`.
- `TrustList`: the payloads (`Listing` to the client, `Toggle` to the server) and the server side.
  The channel is **required**, version "1": a client without the screen is refused at login with
  NeoForge's mod mismatch instead of being let in (the lesson of Backpacks+ 0.5.0 the same day,
  whose unchanged version let 0.4.0 clients in to be kicked at the first chest). Bump it with any
  change to what either side sends.
- `DeedItem`: `use` opens the list; a tooltip line on every deed, old ones included, says so.

## The file (2.0.x per-village lists)

2.0.x saved a `Trusted` list on each claim. `Claims.load` holds those lists per owner, and the
first `Claims.get` folds them onto the owners' rosters (`foldTrusted`: everyone on any of an
owner's villages' lists goes on that owner's one list, so nobody loses access they had anywhere),
then saves the claims without lists. Until the fold, a save still writes the lists, so no order of
events loses a name. On the box, all six claims' lists were empty when this was built (read from
`villagedeed_claims.dat` on 2026-09-27), so the fold moves nobody there; it is for correctness.

`Claims.Claim`'s components and `Deed.of`/`Deed.owner` are unchanged: Magical Map's bridge and its
GameTests build and read claims by reflection with exactly that constructor.

## Rejected

- Keeping per-village lists beside the owner's, for exceptions: Rusty asked for all villages; two
  lists to reason about for a case nobody raised.
- Trusted players sorted first: a clicked name would jump out from under the cursor, the next
  click landing on someone else. The count in the title answers "whom do I trust" instead.
- Sharing Warehouse Manager's per-block rosters: separate mods and separate grants; a warehouse
  and a village are different things to let a friend into.
- An E-inventory tab or a key: offered; Rusty chose the deed and the bare command.
- The roster in the per-dimension claims data: a list would then cover one dimension's villages.
